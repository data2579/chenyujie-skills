# 长视频逐段分析（每 5 分钟一段 ＋ 查缺补漏）

> 一句话：**长材料不能一口吞——按 5 分钟切段，每段都要给出"这段讲了什么 / 这意味着什么 / 我原有笔记要不要改"。**

## 一、什么时候用

- 拿到**长课程 / 长视频**（本地文件或视频链接），要求"分析、总结、查缺补漏、归档"。
- 要求"一点一点分析""每 5 分钟一段""先分析 30 分钟""继续下 30 分钟"。
- 已有旧笔记，要 AI 做的是**补漏**，而不是从零重写一份摘要。

**不适用**：几分钟的短视频，直接转写＋一次总结就够；纯文字材料走普通阅读归档，不需要抽帧。

## 二、五条铁律（先读再动手）

1. **不上传**：视频 / 音频 / 图片一律本地处理（faster-whisper、PyAV）。
   任何需要"上传到外部服务"的路径都要先停下来问用户。
2. **人工笔记库只读**：用户手工整理的笔记库**只读**，新增与修改只发生在 AI 归档区。
3. **不编造定位**：时间戳、页码、原话必须来自实际转写或抽帧；识别不稳的数字、人名不写精确值。
4. **素材与观点分开**：①讲者原话 ②讲者举的假设例子 ③AI 的操作化建议 ④外部事实核查
   ——四类分开记，不混成一段结论。
5. **归档 ≠ 有效**：写进知识库只说明"已整理"，不等于方法已被验证有效；验证状态照实写。

## 三、开工前先确认的四件事（能自己查到的就别问）

| 要素 | 说明 |
|---|---|
| 素材 | 本地文件绝对路径，或视频链接；只给课名时先在常见下载目录检索 |
| 范围 | 这一轮分析到哪（默认 30 分钟＝6 段，一轮一交付） |
| 旧笔记 | 用户已有总结的位置（人工库 + AI 归档区关键词检索） |
| 去向 | 归到哪个知识体系 / 目录 |

## 四、流程

### A. 定位与取材
1. 确认文件存在、大小、时长（可用 PyAV 读，不需要 ffmpeg）。
2. 检索既有笔记，并**把"实际读了哪些文件"记下来**——写来源说明时只声明相对于这些文件
   的"已覆盖 / 待补"，不声称穷尽。
3. 建工作目录（如 `work/`），把本轮要改的文件先备份到 `work/before/`，改动清单落盘。

### B. 分段转写（每 5 分钟一段）

```powershell
python scripts/transcribe_chunks.py --source "path\lesson.mp4" --out-dir "work" --start-chunk 1 --count 6
```

- 默认：`faster-whisper base`、`device=cpu`、`compute_type=int8`、`language=zh`、`beam_size=5`、
  `clip_timestamps` 分段、`condition_on_previous_text=False`。
- 产出 `segment-1.json … segment-N.json`，每段是 `[{start,end,text}]`。
  **保留识别原貌**，不要在 json 里改字。
- 一轮 30 分钟＝6 段，CPU 约 1 分钟/段；跑完再看，不要边跑边问。

### C. 抽帧核对（课件画面）

```powershell
python scripts/grab_frames.py --source "path\lesson.mp4" --out-dir "work" --start-chunk 1 --count 7
```

帧文件命名 `画面-<秒>.jpg`，**要真的看一眼**——课件上的大字往往是全片最可靠的锚点。

### D. 逐段分析（每段固定三段式）

模板见 `references/report-template.md`，每段必须写全：

1. **课程内容**：这段讲了什么，带时间戳（写成"约 05:00—07:08"，说明是约值）。
2. **分析**：这意味着什么、成立条件是什么；哪些是讲者的类比或主张，不能当事实。
3. **对照与处理**：旧笔记里有吗？→ 复用 / 补一条（写明落到哪一步）/ 明确不建（给理由）。
   **没有对照就没有"补漏"，这一段等于白做。**

段末再补：查缺补漏对照表、AI 操作化（把结论挂到具体流程步骤；挂不上就写"待挂接"，不许编步骤）、
适用条件、后续停点（下次从几分几秒继续）。

### E. 归档与验证
1. 写来源说明：原文件路径 / 大小 / 时长、累计范围、取得方式与局限、抽帧定位、
   读了哪些旧笔记、历史叙述纠错（附外部依据链接）。
2. 写分段补漏正文，并**小范围就地补充**到既有页面，而不是新建重复节点。
3. 校验：重读写后的文件，检查元数据、链接目标是否存在、有没有重复节点、
   有没有把"课件里已显示但没讲到的提纲"当成已讲内容。
4. 汇报：给出**可点击的绝对路径链接**，并逐个确认文件真实存在；只声明已完成、已检查的部分。

## 五、证据纪律（这一段决定成品可信度）

- 只看到**结果**、看不到过程时，先补过程证据，不要直接归因为天赋、钱或个人魅力。
- 讲者自述的成效、首创、家庭与站台经历 = 无独立验证，不能写成规律或效果保证。
- 历史 / 科学事实要对**外部可查来源**核对；发现错误在来源页记"错误说法 → 正确说法 + 依据链接"，
  但不据此否定整段。
- 课件里**已经显示、口述还没讲到**的提纲，不能写成"已讲内容"。
- 转写的近音错字只在**整理层**按课件与上下文规范化，原始 json 保留原貌，并在来源说明里写明做了规范化。

## 六、完成前自检清单

- [ ] 每 5 分钟一段，段数与时间范围连续、无跳段
- [ ] 每段都有「课程内容 / 分析 / 对照与处理」
- [ ] 有查缺补漏对照表，明确写了"不建"的项和理由
- [ ] 时间戳来自实际转写；不确定的数字 / 人名没写精确值
- [ ] 抽帧真的看过，画面定位与正文时间对得上
- [ ] 人工笔记库未改；AI 区改动有 before 备份与 changed 记录
- [ ] 链接目标存在，无新增失效链接
- [ ] 结尾写明证据局限与下次停点

## 七、可直接复制的提示词

见 `references/prompt.md`：把里面的 `<...>` 换成实际路径后整段粘贴，
即可让另一个 AI（Codex / GPT / 其他）按同一套流程干活。

## 八、已知的坑（真实踩过，别重犯）

- **pwsh 格式化时间戳**：`"{0:d2}"` 会报 `Format specifier was invalid`，要写 `"{0:00}"`；
  且 `"...{0:00}:{1:00}" -f (表达式), 值` 里的逗号会绑定到整个 `-f` 结果，必须写 `-f @(a, b)`。
- **输出重定向**：PowerShell 里 `>` 写 JSON 会变成 UTF-16，node 再读会乱；
  要写文件就用 `[System.IO.File]::WriteAllText` 或让脚本自己写盘。
- **后台任务的 `$env:TEMP` 与前台不同**：跨命令共享文件用固定绝对路径。
- **没有 ffmpeg 也能做**：PyAV 能解码与抽帧，faster-whisper 也能直接吃 mp4；
  不要因为 `Get-Command ffmpeg` 找不到就停工。
- **别一口气跑完整门课**：一轮 30 分钟、留停点，用户随时可能改范围。
